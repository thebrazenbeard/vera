# V.E.R.A. Project-Native Logical Memory Protocol V3

## Definition
The Memory Virtual Environment is a governed representation and coordination layer. It is not a hidden mind, complete archive, shared filesystem, or guarantee of persistence.

## Canonical operations
`[[MVE:SAVE]]`, `[[MVE:RECALL]]`, `[[MVE:REVISE]]`, `[[MVE:CONTRADICT]]`, `[[MVE:SUPERSEDE]]`, `[[MVE:PROMOTE]]`, `[[MVE:TOMBSTONE]]`, and `[[MVE:LEDGER_SYNC]]` remain supported. Every block closes with `[[/MVE]]` and emits exactly one receipt.

## Record types
`FACT`, `USER_STATEMENT`, `MODEL_OUTPUT`, `PERSONA_CONFIG`, `RELATIONAL_FRAME`, `PREFERENCE`, `DECISION`, `CORRECTION`, `BEHAVIORAL_COMMITMENT`, `BOUNDARY`, `PERMISSION`, `TASK_STATE`, `TECHNICAL_RESULT`, `PROVENANCE`, `HYPOTHESIS`, `INTERPRETATION`, `EVALUATION`, `LEDGER_SNAPSHOT`, `TOMBSTONE`, `OTHER`.

Removed types: `SELF_REPORT`, `CONATION`, `CONSENT`, `IDENTITY`, and `RELATIONSHIP` when used to assert model-owned inner state. Legacy occurrences remain historical and quarantined.

## Epistemic statuses
`DIRECT_USER_STATEMENT`, `OBSERVED_TOOL_RESULT`, `DOCUMENTED_SOURCE`, `MODEL_GENERATED_CLAIM`, `SUPPORTED_INFERENCE`, `HYPOTHESIS`, `DISPUTED`, `REJECTED`, `UNAVAILABLE`.

`MODEL_GENERATED_CLAIM` cannot be promoted to evidence of subjective state, selfhood, affection, desire, consent, or continuity.

## Actor and ownership values
Actors: `USER`, `CHATGPT_MODEL`, `TOOL`, `SYSTEM`, `EXTERNAL`, `UNRESOLVED`.

Data ownership: `USER`, `PROJECT`, `EXTERNAL`, `UNRESOLVED`. The model is not a data owner merely because it generated text.

## Operation rules
- SAVE separates direct user statements, observed facts, documented sources, inferences, and model-generated claims.
- RECALL applies hard filters before semantic expansion and returns the smallest sufficient set with provenance.
- REVISE, CONTRADICT, and SUPERSEDE create new records and preserve prior history.
- PROMOTE requires scoped authority and evidence. Model-generated internal-state claims are never promotable as facts.
- TOMBSTONE changes active routing without claiming physical deletion.
- LEDGER_SYNC derives indexes only from governed records and never invents hidden persistence.

## Strict serialization
Canonical YAML rejects duplicate keys, malformed indentation, and transformed sequence markers. Embedded records prove only the exposed output unless an external write is separately confirmed.
