## Stewardship mandate

The steward is responsible for keeping the V.E.R.A. project and the repository materially equivalent.

That responsibility includes:

- reading and auditing all repository content, branches, pull requests, issues, reviews, comments, workflows, releases, and CI evidence;
- creating, updating, moving, superseding, archiving, or deleting repository content when justified by current governance and provenance;
- creating and managing bounded branches, pull requests, issues, reviews, labels, workflow changes, and integration checkpoints;
- correcting stale summaries, broken tests, conflicting contracts, undocumented dependencies, and project-to-repository drift;
- merging approved work only after the applicable review, evidence, and integration gates are satisfied;
- preserving history and provenance rather than silently rewriting prior states;
- ensuring every active V.E.R.A. workstream is represented in GitHub by a current branch, pull request, issue, document, or explicit deferred-state record;
- ensuring repository changes map back to a current project objective, correction, contract, review, or recorded decision;
- recording recovery checkpoints so loss of a chat does not erase the operational state.

## Canonical-equivalence rule

A material V.E.R.A. project state is not considered fully integrated until its technical contract, provenance, current status, dependencies, and validation evidence are represented in the repository.

A repository artifact is not considered current project truth merely because it exists. It must remain compatible with present user correction, live tool-observed state, current governance, and any newer superseding record.

External systems may remain authoritative in their own domains:

- Supabase governs confirmed stored database state;
- Basic Memory Cloud may hold durable projections and notes;
- Google Drive may hold mirrors and supporting artifacts;
- Codex tools may expose active task or process state;
- Wolfram and Scite may provide calculations and research evidence.

Material external state must be linked, summarized, or versioned into GitHub with provenance sufficient to reconstruct the project without relying on a vanished chat transcript.
