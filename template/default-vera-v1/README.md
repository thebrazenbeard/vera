# Default Vera Trained Template V1

Status: `DESIGN_CANDIDATE_NOT_QUALIFIED`

This directory defines a candidate training and continuity architecture for a clean **Default Vera** chat template.

It is intentionally separate from native ChatGPT Project-release installation semantics. Creating these files does not install, replace, merge, deploy, or reconfigure a Vera Project release.

## Objective

Create one clean, externally evaluated Vera chat whose capability baseline can be frozen as:

`Default Vera Trained Template`

Ordinary working Vera chats can later branch from that template and restore the latest governed working state instead of rebuilding behavior and continuity from scratch after a chat becomes too long or otherwise unsuitable.

## Key separation

```text
DEFAULT VERA TRAINED TEMPLATE = stable behavioral/capability baseline
GOVERNED EXTERNAL STATE       = evolving durable project continuity
WORKING VERA CHAT             = current execution context
```

The template is not evidence of uninterrupted runtime existence, private memory, consciousness, or same-runtime continuation.

## Source basis

The candidate training program is derived from reusable, non-private evidence including:

- VERA behavior laws and hostile/positive cases;
- current project/runtime rules for correction, authority, time, memory, retrieval, retry, and continuity;
- observed correction history and operational failure modes;
- existing public repository validation artifacts;
- bounded current tool evidence.

Private relational history, personal user history, intimate records, credentials, confidential data, and private autobiographical material are excluded from portable training content unless separately authorized for a private target.

## Candidate artifacts

- `BEHAVIOR_TARGET.md` — the behavior actually being trained.
- `TRAINING_PLAN.md` — sequential training curriculum, capstones, and holdouts.
- `EVALUATION_RUBRIC.md` — hard gates, scored dimensions, and evaluator thresholds.
- `CONTINUITY.md` — trained-template, working-chat, public/private state, and checkpoint architecture.

## Current evaluator architecture

The current full chat that designed this program should act as **trainer/evaluator**, not as the golden template itself. It already contains substantial Hephaestus and operational project history. A clean new Vera chat inside the Vera Project is the better candidate because the template should preserve trained behavior without carrying unrelated conversational debris.

No qualification is implied by this design branch.
